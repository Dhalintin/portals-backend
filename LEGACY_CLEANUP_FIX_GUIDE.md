# Batch 13: retire obsolete runtime code

The old PIN checker, unauthenticated result checker, duplicate public-school directory, old settings/academic-session/platform-admin implementations, stateless JWT helpers and duplicate class curriculum code have been moved outside src and dist. Stale compiled modules without matching current source were also retired. Their original contents are preserved under archive/legacy-backend/src and archive/legacy-backend/dist for review and recovery. Active public school branding and the current public directory remain available. Database schema and applied migration history are unchanged.

The central app router now lists only current routes. PIN and old public-result paths remain HTTP 404; they are not redirected to a different access model. Published child results continue through the authenticated parent APIs. Supported school/calendar/platform replacements are the current schools/site, academic, platform and subscription APIs.

`scripts/legacy-retirement.cjs` maintains the retirement list, checks literal relative imports in current source and compiled output, and rejects imports of retired modules or the archive. Before builds/tests it removes only named retired generated artifacts from dist and .test-build. It validates resolved output paths and refuses linked folders/files; it never removes the entire output tree. `npm run legacy:check` verifies the state without changing files. This is an explicit retired-module guard, not a general-purpose dependency analyzer.

`npm run build` now performs this check before and after compilation. `npm start` is the compiled production entry point and checks retirement before launching dist/server.js. Neither starts a build automatically. Keep scripts/legacy-retirement.cjs with the runtime deployment if using npm start, and build before starting. The production start command was added but was not launched against the configured database during this task. Do not include the archive in deployment artifacts.

The active POST /api/v1/staff placeholder has been repaired. It now accepts email, firstName, lastName, role and optional phone, returning HTTP 201 with a pending invitation in data. It does not immediately create an account or membership. Use the existing invitation acceptance flow. Parent invitations belong in the parent APIs; administrator-supplied passwords are rejected. Current invitation permissions, proprietor restrictions and rate limits apply. GET /staff excludes inactive global accounts as well as inactive memberships and other schools.

No dependency installation or migration is required for this batch. Remaining work includes tenant-policy gaps (such as parent profiles across schools), staging configuration, migration rehearsal/backups, real provider smoke tests and deployment/operational checks. Optional spreadsheet uploads/exports and WhatsApp/SMS remain feature work.

Verification: 58 regression tests and 78 isolated PostgreSQL integration tests passed. New HTTP checks cover retired route rejection, preserved public branding/directory routes, rejection of stateless legacy tokens, pending staff invitations, password/parent-role rejection and tenant-scoped active staff lists. The archive contains 46 source files and 78 compiled files. No live database, provider or production server was started.
